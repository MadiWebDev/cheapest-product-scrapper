## 0. Executive summary

The repo is **not** a price-comparison engine yet. It is a single-commit,
image-first **B2B supplier-sourcing** prototype called **SourceLens**: a user
uploads a product photo, GPT-4o Vision guesses a category, and the backend
returns seeded wholesale suppliers from a Postgres table, ranked by a
hand-rolled composite score.

What is sound and worth keeping:

- **Python 3.11 / FastAPI / SQLAlchemy 2 / Alembic / Pydantic v2** backend —
  clean router / schema / model separation, consistent `{success, data, error}`
  envelope, JWT auth, plan-based rate limiting, Celery worker, pgvector-ready
  Postgres, Docker scaffolding, and a 49-row seed dataset across 25 countries.
- The **image-search idea itself**: photo → product understanding is a real
  input mode for this product (brief §2 lists image input as “later”), so the
  GPT-4o Vision + embedding flow is preserved and re-plumbed later, not deleted.

What blocks the goal, in order of severity:

1. **The repo does not run as committed.** Fresh install fails on three
   independent defects (§1.5): `VECTOR` imported from the wrong package,
   `email-validator` missing although `EmailStr` is used, and SlowAPI’s
   `@limiter.limit` applied to handlers with no `Request` argument. The pinned
   `upstash-redis==0.3.0` no longer exists on PyPI at all. All four were
   reproduced 2026-11-15 and fixed only in a scratch copy (§1.7).
2. **The frontend is missing.** `web-application/` is an orphan gitlink
   (`160000`, commit `2d6de21f…`) with no `.gitmodules` and a `null`
   `submodule_git_url` on GitHub — there is nothing to check out. It must be
   rebuilt from scratch (Phase 7).
3. **There is no marketplace, offer, price, or product concept at all.**
   No text search, no barcode/ASIN/URL input, no connectors, no scraping,
   no FX/tax/duty, no price history, no alerts, no quality scoring beyond a
   static 0–10 `trust_score`, and no deduplication. The “matching engine”
   hard-codes `similarity = 0.7` and never runs the pgvector query the README
   describes — the embedding generated by the worker is computed and then
   discarded (the `Search` table has no embedding column).
4. **No tests, no CI, no lint config, no `.gitignore`, no LICENSE, no root
   README.** `backend/.env` (placeholder values) is committed. The seed data
   is 49 (not 50) suppliers, all with `*.example.com` URLs and contact emails.
5. **Security gaps that must be fixed before any public exposure** (§1.6):
   anyone can self-assign the `enterprise` plan at registration; money is a
   `Float`; `TrustedHostMiddleware` allows `*`; the monthly counter is a
   non-atomic check-then-increment; no Celery beat schedule exists for the
   monthly reset the README promises.

**Decision (see `docs/DECISIONS.md` D-001…D-012): keep the Python/FastAPI
stack and evolve it.** Rewriting in Node/TypeScript (the brief’s default)
would discard the only working code in the repo for zero product benefit:
FastAPI + Celery + Postgres/pgvector already cover every Phase 1–12 need,
and the connector/queue/caching design below is language-agnostic. The
frontend is green-field Next.js, as specified.

The target system (§2–§8) is therefore: **FastAPI backend + Celery workers +
PostgreSQL (pgvector) + Redis + Next.js frontend**, with a plugin connector
layer, a country-aware landed-price engine, a transparent quality/value
scoring engine, and a matching/dedup pipeline — delivered phase by phase,
each phase committed only after build + lint + tests pass.

## 2. Target architecture

### 2.1 Principles

1. **APIs first, scraping second.** Every connector tries official
   API/affiliate feed → licensed provider → JSON-LD/structured data →
   Cheerio-equivalent HTML parse → headless browser last. Scraping is a
   fallback, never the first resort (§7).
2. **Landed price is the ranking currency.** No offer is ranked on item
   price alone; every offer carries a computed, explainable landed price
   in the user’s currency (§4).
3. **No silent substitution.** A missing shot — here: a missing offer, a
   blocked connector, an estimated tax — is labelled as such in the UI and
   the API. Cached data carries its age. Estimates carry the word
   “estimate”.
4. **Plugin connectors.** One marketplace = one file + one registry entry.
   Connectors never import each other and never touch the DB directly; they
   return `RawOffer`s (§3.2).
5. **Progressive results.** A slow marketplace never blocks the page:
   search fans out over the queue and streams offers via SSE (§6).
6. **Demo mode is first-class.** With zero API keys the app runs end to
   end on mock connectors + seed data (brief §10). Mock is a connector,
   not a special case in business logic.

### 2.3 Request flows

**Text search (the primary flow, Phase 6)**

```
User query ──► parse (text / GTIN / ASIN / MPN / URL)
        ──► translate query per marketplace locale (cached)
        ──► fan-out: one Celery task per (connector, locale)
        ──► connectors return RawOffer[] (or fail → DLQ + cached fallback)
        ──► normalise → match/dedupe into canonical Products
        ──► landed-price engine (FX + shipping + VAT/duty + fees)
        ──► quality + value scoring
        ──► rank / filter / sort ──► SSE stream to UI progressively
        ──► persist offers + price_history snapshot (async)
```

**Image search (existing flow, preserved)** — upload → Cloudinary →
GPT-4o Vision → category/attributes/keywords → embedding → the same
normalise → match pipeline as text search (instead of today’s
supplier-table lookup). Re-plumbed in Phase 3/6; the upload endpoint,
rate limits, and 30-day expiry semantics are kept.

**URL extraction (generic connector)** — user pastes a product URL →
SSRF-checked fetch (private-IP blocklist, redirect limits, allow-listed
schemes) → JSON-LD `Product/Offer` → heuristics fallback → one `RawOffer`
→ same pipeline.

## 3. Domain model & connector contract

### 3.1 Target data model (PostgreSQL; new in Phase 1, additive to the four existing tables)

| Table | Purpose (key columns) |
| --- | --- |
| `users` (kept, hardened) | + `role user/admin`, `country_code`, `currency`, `locale`, `email_verified_at`, `oauth_provider/subject`; plan is **server-assigned** (fixes B-09) |
| `products` | Canonical product: `gtin, asin, mpn, brand, model, title_canonical, category, attributes JSONB, image_url, embedding VECTOR(1536)` (HNSW index) |
| `offers` | One row per (product, marketplace, seller): `price_amount, price_currency, shipping_amount, availability enum, condition enum, seller_id, rating, review_count, delivery_days_min/max, url, affiliate_url, verified_at, source enum(api/feed/structured/html/browser/cache)` |
| `sellers` | `marketplace, seller_name, feedback_score, feedback_count, account_age, official_store bool, return_policy, buyer_protection` |
| `price_history` | `(product_id, marketplace, country_code, date, price, landed_price, currency)` — append-only, daily snapshot |
| `fx_rates` | `(currency_pair, date, rate, provider)` — daily cache |
| `tax_rules` | Versioned: `(country_code, category, vat_rate, de_minimis, duty_rate, handling_fee, valid_from, valid_to, source)` — **editable in admin, labelled “estimate” in UI** |
| `alerts` / `watchlists` | `(user_id, product_id, target_price, channel email/telegram/push, active)` + delivery log |
| `searches` (kept, extended) | + `query_text, query_type (text/gtin/asin/url/image), country_code, currency, filters JSONB` (image fields kept) |
| `saved_products` | Replaces `saved_suppliers` semantics for products; `saved_suppliers` retained for the legacy B2B flow until Phase 3 decides its fate (see DECISIONS D-011) |
| `api_keys` | Public API: hashed key, owner, scopes, rate-limit tier, usage counters |
| `connector_health` | Per-connector run log: `success_rate, latency_p50/p95, block_rate, last_error, enabled` |

Money is `NUMERIC(19,4)` everywhere (fixes B-10). All timestamps are
`TIMESTAMPTZ`. Every table gets `created_at/updated_at`; soft-delete is
not used — history tables are append-only by design.

### 3.2 Connector interface (one file per marketplace + registry entry)

```python
class Connector(Protocol):
    id: str                    # "amazon", "ebay", "daraz", ...
    name: str
    supported_countries: list[str]   # ISO alpha-2
    supported_currencies: list[str]
    rate_limit: RateLimitPolicy      # req/s, burst, per-domain concurrency
    compliance_note: str             # robots.txt / ToS summary, docs link

    def search(self, query: SearchQuery, filters: Filters,
               country: str) -> list[RawOffer]: ...
    def get_product(self, url_or_id: str, country: str) -> RawOffer: ...
    def health_check(self) -> ConnectorHealth: ...
```

```python
@dataclass
class RawOffer:                 # what a connector returns, untrusted
    marketplace: str
    title: str
    url: str
    image_url: str | None
    price: Decimal | None
    currency: str | None        # ISO 4217, as listed
    shipping_price: Decimal | None
    availability: str           # raw string; normalised downstream
    condition: str | None
    seller_name: str | None
    rating: float | None
    review_count: int | None
    delivery_estimate: str | None
    gtin: str | None
    asin: str | None
    mpn: str | None
    brand: str | None
    model: str | None
    attributes: dict            # colour/size/storage/pack count/...
    source: str                 # api | feed | licensed | structured | html | browser
    fetched_at: datetime
```

Rules: connectors return **raw** data only — no FX, no tax, no scoring,
no DB access. Normalisation, landed pricing, matching and scoring live in
`app/services/` and are connector-agnostic, so a new marketplace cannot
break ranking. Every connector ships with **fixture tests** (recorded
JSON-LD/HTML/API payloads in `backend/tests/fixtures/connectors/<id>/`)
and a **selector-drift detector**: if a parse yields zero offers, zero
prices, or a price outside sane bounds for a query that previously
returned results, the run is flagged, the connector is marked degraded
in admin, and the previous cached result is served with an age label.

Fallback chain per connector (§2.1 principle 1), with automatic switching
and per-source cost accounting (admin shows cost per provider).

**Connector build order:** Phase 2 — Amazon, eBay, Etsy, Google Shopping,
AliExpress + generic URL extractor (+ mock connectors for demo mode).
Phase 9 — Daraz, Flipkart, Noon, Jumia, Lazada, Shopee, Mercado Libre,
Allegro, Rakuten, Coupang, Takealot, OLX, Zalando, OTTO, Cdiscount,
Trendyol, Ozon, Walmart, Target, Best Buy, Newegg, Temu, Alibaba.
(Regional ordering follows the brief; Walmart/Target/Best Buy/Newegg/Temu
are listed in the brief’s global group but are US-centric, so they land in
Phase 9 with the other regionals unless their official APIs prove trivial
in Phase 2 — see DECISIONS D-005.)

### 3.3 Normalisation, matching, dedup (Phase 3)

```
RawOffer ──► normalise (currency, availability enum, condition enum,
│                       strip tracking params, sanitise HTML/text)
│
├─► identity keys: GTIN/UPC/EAN → ASIN → MPN → (brand + model regex)
├─► fuzzy title match: token-set ratio ≥ threshold
├─► optional embedding similarity (pgvector, same 1536-dim space as today)
├─► attribute check: colour / size / storage / pack count / variant
│
└─► canonical Product + offers[]
    look-alikes separated: accessories, cases, bundles, other variants
    never merge into the "cheapest" group. "Report wrong match" feeds
    a rules table (exact-match overrides + blocklist pairs).
```

## 4. Country-aware landed pricing (the core differentiator)

```
Landed = item price
       + shipping to user's country
       + VAT / GST / sales tax (destination-based, from tax_rules)
       + import duty (category rate, only above de-minimis)
       + customs / handling fees
       + payment & FX-conversion margin
       (all converted at the daily cached FX rate, fallback provider on miss)
```

- **Country detection:** IP geolocation with manual override; the override
  is stored on the user profile and wins over IP on every visit.
- **FX:** daily-cached rates from a free provider (e.g. Frankfurter/ECB),
  fallback provider on failure; every converted price records
  `fx_rate + fx_as_of` so the UI can show staleness.
- **Tax/duty tables:** `data/tax_rules/` as versioned, editable tables
  (CSV + seed migration), with `valid_from/valid_to` and a source column.
  The UI labels every computed tax/duty line **“estimate”** unless the
  marketplace API returned an exact landed cost.
- **Breakdown:** every result card exposes item / shipping / tax / duty /
  fees / FX on hover; each line is tagged `exact` or `estimated`.
- **Availability by country:** offers that cannot ship to the selected
  country are excluded from ranking and shown in a collapsed
  “Not available in your country” section — never silently dropped, never
  ranked as buyable.
- **Re-verification:** top-N results are re-fetched live before display;
  each offer shows “last verified X minutes ago”.

## 5. Quality & value scoring

**Quality Score (0–100, transparent, with per-factor explanation):**

| Factor | Signal |
| --- | --- |
| Rating | Bayesian average (corrects low review counts) |
| Review volume & recency | Volume, and recency-weighted |
| Fake-review heuristics | Rating-distribution anomalies, review bursts, repeated phrasing, unverified-purchase ratio (where available) |
| Seller reputation | Feedback score, account age, return rate, official/brand-store badge |
| Condition & warranty | New/used/refurbished/open-box, warranty length |
| Counterfeit risk | Price far below market median for a branded product + new seller + generic images |
| Return policy & buyer protection | Policy length, protection coverage |

**Value Score** = weighted combination of quality, landed price, delivery
time, availability. Default weights are user-adjustable via sliders
(price / quality / speed / reliability) and stored per user. Sort modes:
best value (default), lowest landed price, lowest item price, best quality,
fastest delivery, biggest verified discount. **Fake-discount detector:**
“was” price vs the real 90-day median from `price_history`; an inflated
“was” is flagged, not celebrated.

## 6. Search API, streaming & caching

- `POST /api/v1/search` — validated query (text / GTIN / ASIN / MPN / URL /
  image-search id), filters (§2 of the brief), sort, pagination.
  Response: canonical products with grouped offers.
- `GET /api/v1/search/stream?job_id=…` — **SSE**: one event per connector
  as it answers (`offer_batch`, `connector_done`, `connector_failed`,
  `search_complete`). A slow site never blocks the page.
- `GET /api/v1/products/{id}` — offers table, price-history chart data
  (30/90/365d, low/avg/high, “good time to buy?”), specs, similar products.
- `GET /api/v1/products/{id}/history`, `POST /api/v1/watchlists`,
  `POST /api/v1/alerts`, `GET /api/v1/trending/{country}`.
- Saved searches, shareable result URLs (encoded query + filters, no
  user data in the URL), export CSV/XLSX/JSON.
- **Caching:** query cache (short TTL, keyed on normalised query +
  country + currency + filters), product cache, FX cache;
  stale-while-revalidate for price history. Cache keys never contain
  PII or tokens.
- **Queue:** Celery (kept) — one task per (connector, locale), per-domain
  concurrency + rate limits, retries with exponential backoff, circuit
  breakers, dead-letter queue. Task payloads carry `job_id` for SSE
  correlation. (BullMQ was the brief’s default; Celery is the equivalent
  already in the repo — DECISIONS D-002.)

## 7. Responsible scraping & compliance

- Prefer official APIs and licensed data. Every connector file carries a
  `compliance_note` (robots.txt + ToS summary + date checked) and the
  docs carry a per-connector table (`docs/COMPLIANCE.md`, Phase 2+).
- Polite crawling: per-domain rate limits, jitter, conditional requests,
  caching, a clear identifying User-Agent.
- Proxy/session handling behind an adapter (rotating residential/datacenter
  proxies via env config, geo-targeted so prices match the selected
  country). No proxy config is required for demo mode.
- **No CAPTCHA-solving and no login-wall bypassing, ever.** On a block:
  fall back to the next source in the chain → serve cached data with an
  age label → flag the connector degraded in admin.
- Never store personal data from scraped pages. All scraped HTML/text is
  sanitised before rendering (XSS-safe); product images are served via
  the image proxy, not hot-linked with tracking params.
- SSRF protection on the URL extractor: private-IP/range blocklist,
  redirect cap, scheme allow-list (`https` only, plus `http` for
  explicitly allow-listed hosts), response-size cap, timeout.
